# Module 4 on one page: Multi-Agent Systems

| Lesson | Keep this |
|---|---|
| 4.1 Coordinators and subagents | Hub and spoke: the coordinator owns routing, error handling and the flow of information; subagents report to it, never to each other. Each subagent runs in its own conversation and only its final message returns to the parent. The coordinator picks subagents by what the query needs (a single known page needs only the analyst), not the full pipeline every time. A subagent starts with only its prompt: every constraint it needs (the URL, what to extract, what to do if the page fails, report the source per fact) goes in that prompt. |
| 4.2 Subagents in the Agent SDK | `AgentDefinition`: `description` (when to use it: how the coordinator picks), `prompt`, `tools` (`[]` = none), `model`. The coordinator needs the Agent tool in its tools and `allowed_tools` (⚑ the exam guide calls it `Task`, its earlier name; the init tool list still says `Task`, tool calls say `Agent`). Hand findings over complete, as structured data that keeps content (claim, evidence) apart from metadata (URL, publisher, date, method), never as a prose summary. |
| 4.3 Parallel subagents, scope and refinement | Independent subtopics run at the same time: several Agent calls in one response; they finish in the time of the slowest one (our run: 98 s of work in 57 s). Partition by subtopic or by source type so the scopes don't overlap. Give the coordinator a goal and the criteria for a good answer, not step-by-step orders, and a refinement loop: check coverage, send targeted work on the gaps, then synthesize. |
| 4.4 Choosing a decomposition strategy | Known, repeatable steps: a fixed chain (easier calls, more latency; 6 calls fixed before the run). An open investigation: a dynamic plan that adapts to what it finds (14 tool calls chosen during the run). A big review: per-file passes for local problems plus a cross-file pass for what no single file shows. |
| 4.5 Distributing tools across agents | Each role gets only the tools it needs; a tool left out isn't in the subagent's session at all. Swap a general tool for a constrained one (`load_document` opens only what the searchers found, instead of a `fetch_url` that guesses links). For a frequent cross-role need, one scoped tool (`verify_fact`: a claim and its URL); route everything else through the coordinator. |
| 4.6 Errors across agents | A failed tool call returns structured error context: the failure type (timeout, not found, auth...), whether it's retryable, the query, partial results and alternatives, with `is_error` set. Never an empty success (it turns "we couldn't look" into "nothing exists") and never an abort of the whole run. Recover locally (retry a brief failure once, reword), propagate what's left to the coordinator, carry on, and name the gap in the answer ("Not covered: ..."). |
| 4.7 Provenance and conflicting sources | Every claim keeps its source (URL, publisher, date, excerpt) through every hand-over and summary. Conflicting figures stay side by side, each with its source, measure and date (24.0% of order value from a survey; 17.6% of units from transactions); never an average or a silent winner. Dates show change over time, not a conflict. Separate established from contested, flag a source with no stated method, put key findings first under headers, tables for data and prose for narrative. Check it in code: a test for every claim's source. |
| 4.8 State, crash recovery and context budgets | Save each agent's report to a file as it lands and update a manifest atomically (write a temp file, then rename); on a rerun, resume from the manifest and run only what's missing. Keep in the coordinator's context only what the run needs. Upstream agents hand over compact facts with relevance and metadata (or lightweight references), not their whole reasoning. |

## The seven traps

| Trap | It sounds like | Why it's wrong, and the fix |
|---|---|---|
| Hand out every tool | "Give every agent every tool." "Let the analyst search too, just in case." | More tools blur each role: agents wander, guess links and do each other's work. Only each role's own tools; a constrained tool instead of a general one; one scoped cross-role tool (`verify_fact`); the rest through the coordinator. |
| Assume shared memory | "The subagent can see the conversation." "It already knows the date range." "The coordinator's summary is enough." | A subagent starts with only its prompt and inherits nothing; a prose summary drops sources, dates and methods. Every constraint in the prompt; complete findings as structured data (claim, evidence, URL, publisher, date). |
| Blame the synthesizer | "Give the synthesis agent a better model." "Tell it to cover more." | The writer writes what it receives: a missing area was never assigned or was dropped at a hand-over. Read upstream first (the coordinator's split, each hand-over), and add a refinement loop that finds gaps and sends targeted work out. |
| One shape for every task | "Always decompose dynamically." "Fix the investigation's steps in advance." "Run the subagents one at a time to be safe." | Known steps suit a chain; an open investigation needs a plan that adapts; a big review needs per-file plus cross-file passes; independent subtopics run in parallel (several Agent calls in one response). |
| Swallow or abort | "Return an empty list so the run never stops." "Stop the whole run on any error." "Retry until something comes back." | An empty success hides a failure; an abort throws away finished work; endless retries burn time. Structured error context (type, query, partial results, alternatives); retry brief failures locally; carry on; name the gap. |
| Pick a winner | "Report the average." "Keep the larger sample." "The newer figure replaces the older one." | Figures can measure different things (order value vs units): an average is a number nobody measured; different years may show change over time. Keep each figure with its source, measure and date; established vs contested; flag a source with no method. |
| Start over | "Run everything again after a crash." "Write one summary at the very end." "Use a bigger context window." | A restart repeats every search; an end-of-run summary dies with the run. Save each report as it lands with an atomic manifest and resume from it; compact hand-overs with relevance and metadata. |

Each of these moves is a real tool somewhere: a chain for known steps, one subagent at a time when each step needs the last one's result, dropping a figure that is simply wrong and flagged, a fresh start when the saved state is invalid. It's wrong when it replaces what the question actually asks for. And in a multi-agent question, the agent that shows the failure is rarely where it starts.
